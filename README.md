# 개인 가계부

수입과 지출을 기록하는 가계부 웹앱입니다.

## 현재 상태

만드는 중입니다. 화면(`frontend/`)과 서버(`backend/`)가 연결되어 있고, 기록 적기, 목록 보기(순서 바꾸기), 기간별로 보기, 합계, 기록이 없는 기간 안내, 지우기, 실패 알림(서버에 연결되지 않음, 이미 지워진 기록, 그 밖의 서버 오류)이 동작합니다. 문서는 README.md, AGENTS.md, DECISIONS.md, PLAN.md, PRD.md, ARCHITECTURE.md, SCREEN-SPEC.md, DATA-MODEL.md, API-SPEC.md, TEST-PLAN.md가 있습니다. PLAN.md의 P-04(PRD.md 작성)를 마쳤고, 첫 버전 기능 범위는 DECISIONS.md의 D-002와 D-011로 정했습니다. 저장 방식, 본인 확인 방법, 화면 기술, 서버 기술, 데이터베이스, 호스팅, 메일 발송은 D-003~D-012로 정했습니다. P-05(ARCHITECTURE.md 작성)를 마쳤습니다. P-06(SCREEN-SPEC.md 작성)을 마쳤습니다. 돈·날짜 규칙은 D-013, D-014로 정했습니다. P-07(DATA-MODEL.md 작성)을 마쳤습니다. 로그인 유지 방식은 D-015로 정했습니다. P-08(API-SPEC.md 작성)을 마쳤습니다. 2026-10-14에 결정을 바꿨습니다(D-016 ~ D-022). 로그인 기능을 빼고, 집 컴퓨터 한 대의 크롬에서만 쓰며, 서버는 Python + FastAPI, 데이터베이스는 SQLite로 합니다. 이에 맞춰 ARCHITECTURE.md, SCREEN-SPEC.md, DATA-MODEL.md, API-SPEC.md를 고쳤고, 이 네 문서는 2026-10-14에 다시 승인했습니다. P-09(TEST-PLAN.md 작성)를 마쳤습니다(2026-10-14). 검증은 자동 테스트와 컴퓨터의 크롬에서 직접 확인하는 방법을 함께 씁니다. 이로써 PLAN.md의 이번 목표(P-04 ~ P-09, 기획·설계 문서 작성)를 모두 마쳤습니다. 다음 목표는 "PRD Must를 동작하는 웹앱으로 만들기"로 정했습니다(PLAN.md P-10 ~ P-20, P-16은 뺌). P-10(도구 확인), P-11(화면 틀)을 마쳤습니다(2026-10-14). 화면 틀은 S-05의 버튼과 글자만 있고, 눌러도 아직 아무 일도 하지 않습니다. P-12(서버 틀)를 마쳤습니다(2026-10-14). 서버는 분류·결제 수단 목록(A-10)만 돌려주고, 켤 때 SQLite 파일에 기록 표를 만듭니다. P-13(화면·서버 연결)을 마쳤습니다(2026-10-14). 서버가 빌드한 화면과 API를 같은 주소(`http://localhost:8000`)에서 내보내고, 화면은 열 때 분류·결제 수단 목록을 불러옵니다. P-14(기록 적기)를 마쳤습니다(2026-10-15). [+ 기록 적기]로 기록을 적어 저장할 수 있고, 화면과 서버가 같은 규칙으로 입력을 검사합니다. P-15(목록·새로고침 유지)를 마쳤습니다(2026-10-15). 앱을 열면 이번 달이 최근 순으로 보이고, 순서·기간을 바꿀 수 있으며, 새로고침해도 기록이 그대로 있습니다. (P-16은 뺐습니다.) P-17(삭제)을 마쳤습니다(2026-10-15). 기록의 [지우기] → "정말 지울까요?"에서 [예]를 누르면 지워지고, 지운 기록은 되살릴 수 없습니다. P-18(실패 안내)을 마쳤습니다(2026-10-15). 실패하면 화면 맨 위에 알림이 보이고, 적던 내용은 남습니다. 서버는 데이터베이스 파일을 열지 못해도 켜지며, 그동안의 요청에는 오류를 돌려줍니다. 다음은 P-19(껐다 켜고 다시 실행)입니다.

이 앱에는 AI 기능을 넣지 않습니다.

## 프로젝트 문서

- `README.md` — 이 파일. 프로젝트 소개와 현재 상태, 시작·실행 방법을 적습니다.
- `AGENTS.md` — AI가 이 프로젝트에서 일할 때 지키는 작업 규칙입니다.
- `DECISIONS.md` — 사람이 확정한 결정을 기록합니다.
- `PLAN.md` — 이번 목표와 범위, 작업 목록과 진행 상태를 적습니다.
- `PRD.md` — 첫 버전의 요구사항 후보와 검토 내용을 적습니다.
- `ARCHITECTURE.md` — 전체 구조, 사용할 기술과 실행 환경, 구성 요소와 책임, 데이터·실패 흐름을 적습니다.
- `SCREEN-SPEC.md` — 화면 목록과 이동 흐름, 화면별 입력 칸·버튼·알림 문구, 지원 브라우저를 적습니다.
- `DATA-MODEL.md` — 데이터베이스에 저장하는 정보의 항목과 형식, 금액·날짜·글자 수 규칙, 분류·결제 수단 목록을 적습니다.
- `API-SPEC.md` — 화면과 서버가 주고받는 요청과 응답, 오류 응답을 적습니다.
- `TEST-PLAN.md` — 기능별 확인 방법(서버·화면 자동 테스트, 크롬에서 직접 확인), 테스트 환경, 확인 항목과 기대 결과를 적습니다.

## 시작 방법

1. 이 폴더를 엽니다.
2. 이 README.md를 처음부터 끝까지 읽습니다.
3. "현재 상태"에서 지금 어디까지 만들어졌는지 확인합니다.

## 실행 방법

Node.js 22와 Python 3.12가 있어야 합니다. 명령은 프로젝트 맨 위 폴더에서 시작합니다.

**처음 한 번만 준비**

1. 화면 패키지: `cd frontend` → `npm install`
2. 서버 패키지: `python -m venv .venv` → `.venv\Scripts\python -m pip install -r backend\requirements.txt`

**앱 쓰기 (화면과 서버를 함께 켜기)**

1. 화면 빌드: `cd frontend` → `npm run build` (화면을 고친 뒤에는 다시 빌드)
2. 서버 켜기: `cd backend` → `..\.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`
   - 기록은 `data/expense.db`에 저장됩니다.
   - 직접 확인용 데이터베이스로 켜려면 먼저 환경 변수를 정합니다. PowerShell: `$env:EXPENSE_DB_PATH = "..\data\expense-check.db"`
3. 크롬에서 `http://localhost:8000` 열기. 화면과 API가 같은 주소에서 나옵니다.

**개발할 때 (화면을 고치며 바로 보기)**

1. 위 2번처럼 서버를 켭니다.
2. 다른 창에서 `cd frontend` → `npm run dev` → 크롬에서 `http://localhost:5173` 열기
   - `/api` 요청은 개발 서버가 `127.0.0.1:8000`으로 넘겨줍니다.

**자동 테스트**

- 화면: `cd frontend` → `npm test`
- 서버: `cd backend` → `..\.venv\Scripts\python -m pytest` (테스트마다 임시 데이터베이스를 씀)
